# 07 图片

> 状态：v1 现状（**按实现反推**）+ v2 目标（标注清楚哪句是现状、哪句是 v2 变更）。
> 强制级别：**MUST** / **SHOULD** / **MAY**。
> 「三端」= 主机（内嵌服务端的一端）、独立部署的服务端、客户端。未标「v2」的条目 = v1 现状且继续有效。
> 本文件只写**图片域自己的语义**：端点字段表见 `04-http-api.md` §1.3.3–1.3.4，体积与限流的传输层约束见 `02-transport.md` §1.4–1.5，错误码语义见 `09-errors.md`，能力名 `image_fetch` 见 `11-capabilities.md`，哈希与标识符通则见 `01-conventions.md` §1.3。

## 1. 规则

### 1.1 上传端点与 multipart 形态
- **MUST** 上传 = `POST /api/v1/images`，需鉴权（缺/错 token → `401`，且**早于**限流计数）；请求体 `multipart/form-data`。
- **MUST** 图片字节放在字段名 **`file`** 的 part 里；只看**第一个** `file` part，之后立刻返回，后续同名 part 忽略。
- **MUST NOT** 把 part 的**文件名**当契约的一部分：现状接受任意文件名（向量 2–3、9–12 用了 `a.jpg`、`empty.jpg`、`big.jpg`、`q.jpg`，回放器可自造）。
- **MUST** 请求不是 multipart / 没有 `file` part / `file` part 长度为 0 → `400 invalid_request`（空文件见向量 9）。
- **MUST** 上传**不做**内容嗅探、不转码、不缩放、不算尺寸：收到的字节原样落盘。
- **MUST** 成功 `200`，体为 `image_hash` / `size` / `mime` / `width` / `height` / `existed`；`size` = **实际收到的字节数**，`mime` 恒 `"image/jpeg"`（向量 2）。
- **MUST** `width` / `height` 现状**从不计算**：首次上传恒为 `null`；只有既有行带过尺寸时才回填那个旧值（尺寸列为 v2 目标，见 §1.8）。

### 1.2 内容寻址与去重
- **MUST** `image_hash` = sha256(**完整字节**) 的小写十六进制 64 位：客户端对**压缩后**要发出的 JPEG 字节算，服务端对**收到**的字节算 —— 同一字节序列两端必然一致。**MUST NOT** 在传输途中改字节（改字节即换内容地址）。
- **MUST** 同一字节序列再传一次：回**同一个** `image_hash`、`existed: true`、`size` 不变（向量 3）；**MUST NOT** 产生第二行、第二个文件。
- **MUST** `existed` 的判据是「处理本次请求**之前**，该 hash 在图片表里已有行」，**不是**「文件已在磁盘上」。
- 现状（可依赖）：行以 hash 为主键**合并**，不是「只读幂等」—— `created_at` 沿用既有行的值；`size` / `mime` / 上传者用**本次请求**的值覆盖（同字节时前两者必然相同）；`local_path` 只在本次能算出路径时覆盖，算不出则**保留旧值**；文件**仍会重写一次**（写同样的字节）。
- **SHOULD NOT** 用 `existed` 判断「图还在不在本机磁盘上」：那是 `local_path` 的语义（§1.7）。
- **MUST** 上传响应的键是 `image_hash`，图片实体的键是 `hash`（`01-conventions.md` §4 已列此分叉）：解析端**两个名字都要认**。

### 1.3 体积闸门（两阶段）
- **MUST** 单文件上限 **2097152** 字节（2 MiB），两道闸门都必须有：
  1. **预检**：请求头 `Content-Length` 存在且 > **2162688**（= 上限 + 64 KiB）→ 立刻 `413 payload_too_large`，**不解析表单、不读正文**；
  2. **边收边计数**：逐块累计，一超过 **2097152** 立即 `413` 并**停止读取**（分块传输没有 `Content-Length`，只有这道拦得住）。
- **MUST NOT** 把整包读进内存再判大小；**MUST NOT** 等整包收完 —— 向量 10 用 2097153 字节钉住「不等整包」。
- **MUST** 限流检查排在**体积检查之前**：被 `400` / `413` 拒绝的上传**同样消耗**额度（向量 11 的额度由「1KB + 同图 + 空文件 + 超限」各计一次凑满）。
- **MUST** 提前返回（`413` / `400` / `429`）前把**已经在路上**的请求体读掉（最多等 **300 ms**、丢弃上限 = 上限 + 8 MiB）：带未读数据的关闭会发连接重置，客户端拿到的会是「网络错误」而不是真正的错误码。**MUST NOT** 为此等到整包收完（客户端可能永不结束请求体）。

### 1.4 下载端点与 hash 白名单
- **MUST** 下载 = `GET /api/v1/images/<hash>`，需鉴权（向量 13、14：上传与下载无 token 都是 `401`）。
- **MUST** `<hash>` 必须匹配 `^[0-9a-f]{64}$`（**小写**）；形态不符**一律** `404 not_found`，且**不接触任何文件**。这是安全边界：hash 直接拼成文件名 `<图片目录>/<hash>.jpg`，而 Windows 上 `\` 也是路径分隔符，`..%5C..%5C` 会读到图片目录之外（向量 8；大写同属形态不符，向量 7 用 `not-a-hash`）。**MUST NOT** 放宽。
- **MUST** 形态合法但文件不存在（或读不出）→ `404 not_found`（向量 6）。两种情况**同一个 code、同一个状态码**，客户端无法区分「hash 形态非法」与「图不存在」，也**不需要**区分。
- **MUST** 命中 → `200`，响应体是**原始字节**、`content-type: image/jpeg`（恒此值、不嗅探）；**MUST NOT** 包成 JSON。向量 4–5 用「响应体字节的 sha256 == `image_hash`」证明取回的就是上传的那张图。
- **MUST** 下载是只读：不消耗上传额度、不支持范围请求；现状**不按上传者隔离** —— 任何已配对设备可读任意 hash。

### 1.5 上传限流
- **MUST** 每设备 **30 次 / 60000 ms** 滑动窗口，按**已认证设备**分别计数（数值与判据见 `02-transport.md` §1.5）。
- **MUST** 第 31 次起 `429 rate_limited` + `retry_after_seconds`（整秒、向上取整 = 窗口内最早一次上传满 60 秒的剩余秒数）：向量 11 把额度用满 → 12 被拒且 `retry_after_seconds` 匹配 `^[0-9]+$`。
- **MUST** 客户端按 `retry_after_seconds` 退避，**MUST NOT** 立即重试（`09-errors.md` §1.3）。

### 1.6 本地缓存与剪枝（客户端）
- **MUST** 把本地原图当**缓存**：文本结果与元数据**永久保留**；剪枝只删本地文件并把 `local_path` 置空，**不动**图片行、题目与历史。
- **MUST** 安卓端固定保留最近 **20** 张本地原图（不可配置），超出时按 `created_at` **最旧优先**删除 —— 是「最早登记的」而非「最久未访问的」。
- **MUST** **离线队列里任务引用的原图不参与清理，也不计入这 20 张额度**：队列上限（20 条）与本地上限（20 张）同量级，按时间剪会把队首任务的原图先剪掉，那条任务之后每次补跑都取不到原图、永久失败。
- **MUST** 删除文件失败（被占用 / 无权限）时仍然断开关联（`local_path` 置空），避免每轮重复尝试。
- 现状（主机端）：上限是**本机设置项**，默认 **60**，`0` = 不设限。
- **MUST** 补传只针对 `local_path` 为空的行，候选只看**最近 200 张**、一次最多 **5** 张；下载成功写回 `local_path`，使「库里有记录、文件却不在」的状态自愈。

### 1.7 `local_path` 与占位
- **MUST** `local_path` 是**本地专属列**：**不进**同步 op、**不被**远端 op 覆盖；单独写这一列**不产生** op。
- **MUST** 图片的显示**不依赖** `local_path`：主机缩略图在 `local_path` 为空（或指向的文件已不在）时**回落**到约定路径 `<数据目录>/images/<hash>.jpg`，仍找不到才显示占位图标。
- **SHOULD** 任何把图片落盘的端都写回 `local_path`（主机收到上传后即写）。只改这一列时 **MUST** 显式写一次：通用合并逻辑不把 `local_path` 视为「有变化」，否则会走「无变化 → 直接返回」的短路，历史数据永远补不回来。
- **MUST** 同步载荷里的图片元数据**不含** `local_path`：快照的 `images` 在序列化后剔除该键（本地路径对别的端既无用、又泄漏主机目录结构）。
- 现状：图片目录里只有一份内容文件 `<hash>.jpg`；**没有**协议层面的缩略图对象，占位是界面行为。

### 1.8 v2 目标（**变更**，尚未实现）
1. **分块 / 断点续传上传**：新增「创建上传 → 分块 → 提交」的会话式端点，一次性 `POST /api/v1/images` 作为兼容子集保留。
2. **Provider 取图**：Provider 角色按 hash 取图（能力名 `image_fetch`），并明确「谁可读谁的图」的隔离规则；现状是任何已配对设备可读任意 hash。
3. **`width` / `height` 真算**：上传时解出真实尺寸并落库，不再恒 `null`。

## 3. 一致性向量覆盖

| 规则 | 覆盖它的向量（`images.ndjson`） |
|---|---|
| 上传成功体与 `existed` 初值 | 2（`size` / `mime` / `existed:false`、`image_hash` 匹配 `^[0-9a-f]{64}$`） |
| 内容寻址去重（同字节 → `existed:true`、同 hash） | 3 |
| 下载字节与原图逐字节相同 | 4、5（`body_sha256` = `$hash`） |
| 形态合法但不存在 → 404 | 6 |
| 非 64 位小写 hex / 目录穿越 → 404 | 7、8 |
| 空文件 → `400 invalid_request` | 9 |
| 超限 → `413`（边收边判，不等整包） | 10 |
| 30 次 / 分钟；第 31 次 `429` + 整秒 `retry_after_seconds` | 11、12 |
| 上传与下载都要求鉴权 | 13、14 |

## 4. 文档-实现分叉

| 现有契约怎么写 | 实现是什么 | 处置 |
|---|---|---|
| 上传响应示例给出 `"width": 1600, "height": 900` | 上传接口**从不计算**尺寸，首次恒 `null`；`mime` 也恒 `image/jpeg`（不嗅探） | 按现状写（§1.1），尺寸列为 v2 目标 |
| 「客户端限流：每分钟 30 次」 | 服务端按**调用设备**统计；未认证请求在限流前 `401`（不计数），被 `413`/`400` 拒绝的请求**照常计数** | §1.5 按现状写明 |
| 只有「服务端按 hash 去重」一句 | 去重的同时**仍重写文件**，并可能改写行内 `size`/`mime`/上传者；`created_at` 沿用旧值 | §1.2 写明「幂等但非只读」 |
| 未提 hash 形态白名单 | 下载端点强制 `^[0-9a-f]{64}$`，不符一律 `404`（挡住路径拼接） | §1.4 升为安全边界 |
| 未提下载也要鉴权、也未提「不按上传者隔离」 | 下载与上传一样要求 token；任何已配对设备可读任意 hash | §1.4 |
| 未提本地上限与剪枝细节 | 安卓固定 20 张、最旧优先、队列引用者豁免；主机端可配置（默认 60，`0` = 不设限） | §1.6 写明数值与豁免规则 |
| 未提 `local_path` 是本地专属列 | 不进 op、不被远端覆盖；**且快照的 `images` 已经剔除该键**（`04-http-api.md` §1.4.5 第 4 条仍把它列为 v2 目标） | §1.7 按现状写；该条 v2 目标实际已落地一部分 |

## 5. 待确认

1. **同字节重传会不会清掉既有行的尺寸**：上传处理器按 `null` 提交 `width` / `height`，而落库映射把「键存在且值为 `null`」当成**显式写 NULL** → 既有行本来有尺寸时可能被清空；而响应里回的是**写入前**读到的旧值，两者会不一致。未见测试覆盖。
2. **`Content-Length` 预检那道闸门没有向量**（向量 10 落在边收边计数上），也没有「多个 `file` part」与「缺 `file` part」的向量；本文件的相应条目目前只有代码依据。
3. **`images.ndjson` 4 与 5 是完全重复的两步**（`04-http-api.md` §3 已注记为待确认）：本文件按「两次下载都成立」引用，未假定两步有不同目的。
4. **安卓 20 张是写死的常量**，而设置模型里仍留着同类字段（不再读取）：「字段是否删除」属客户端实现，不进契约。
