# 02 传输层

> 状态：v1 现状（**按实现反推**）+ v2 目标（标注清楚哪句是现状、哪句是 v2 变更）。
> 强制级别：**MUST** = 三端必须做到；**SHOULD** = 有理由才能偏离；**MAY** = 可选。
> 「三端」= 主机（内嵌服务端的一端）、独立部署的服务端、客户端。未标「v2」的条目 = v1 现状且继续有效。

## 1. 规则

### 1.1 监听与寻址
- **MUST** 主机监听 IPv4 通配地址 `0.0.0.0`（不是某一个局域网地址）。
- **MUST** 默认端口 **8765**；被占用则依次尝试 **8766 → 8770**（连默认端口共 6 个）。
- **MUST** 6 个端口全部被占用 = **启动失败并报错**；**MUST NOT** 静默改成范围外的端口。
- **MUST** 端口必须是可被探测到的：占用即绑定失败并换下一个（现状：非共享绑定，同一端口不允许两个监听者）。
- **MUST** 实际生效的端口就是配对二维码与用户手输里给客户端的端口。
- **MAY** 端口 0 = 由系统分配随机端口；仅用于回环自检，**MUST NOT** 作为分发默认值。

### 1.2 协议与形态
- **MUST** HTTP/1.1 + WebSocket 升级，**共用同一个端口**；WS 路径固定 `/ws`。
- **MUST** 全程明文（`http://` / `ws://`）：局域网直连、不做 TLS/HTTPS，这是产品决策，异常设备用「吊销」兜底。
- **MUST** 客户端允许对局域网 / 回环地址发明文请求；**MUST NOT** 因为这个原因要求用户配证书。
- **MUST** 路由只按**路径**匹配，且静态路径排在参数路径之前（`/api/v1/tasks/active` 不得被 `/api/v1/tasks/{task_id}` 抢走）。
- **MUST** 请求体按流式处理：服务端不得先把整个上传读进内存再判体积。
- **MUST** 同一个 `device_id` 的 WS 只保留一条连接（新连接踢旧连接，见 `05-websocket.md`）。

### 1.3 超时（现状）
- **MUST** 客户端按「建连 **5s** / 读 **30s**」配置超时；发送请求体**未设**超时（现状：无上限）。
- **MUST** 服务端未显式设置请求超时（现状：未在实现中固定；运行时的空闲连接回收不作为契约）。
- **MUST** 客户端把传输层失败统一翻译成自己的错误（现状：`code=timeout` 或 `network_error`，HTTP 状态写作 0），**MUST NOT** 把底层网络异常直接抛给上层。
- **MUST** 客户端响应不是 JSON、或状态码非预期时同样归一成上述错误，不得崩在解析里。
- **MUST** WS 心跳：服务端每 **30s** 发 `ping`；客户端「**>40s** 没收到服务端 `ping`」（= 30s + 10s 容差）即判定连接已死并重连。
- **v2 变更** 上传单独 120s；AI 调用 90s；服务端**校验** `pong`、90s 断开死连接。

### 1.4 体积上限（图片）
- **MUST** 单张图片 ≤ **2 MiB** = 2097152 字节，按**实际收到的字节数**判定。
- **MUST** 两阶段判定，两道都必须有：
  1. **预检**：`Content-Length` 存在且 > 2097152 + 64 KiB = **2162688** → 立刻 413，**不读 body**；
  2. **边收边计数**：累计字节 > 2097152 → 立刻 413，**停止读取，不等整包收完**（分块传输没有 `Content-Length`，只有这道拦得住）。
- **MUST** 超限 = `413 payload_too_large`；空文件 = `400 invalid_request`；缺 `file` 字段 = `400 invalid_request`。
- **MUST** 提前返回 4xx（413 / 400 / 429）时尽力读掉**已经到达**的请求体（现状：最多等 300ms，丢弃上限 = 2097152 + 8 MiB），避免连接被重置导致客户端收到「网络错误」而不是真正的错误码；**MUST NOT** 为此等到整包收完。
- **v1 现状** 其它 JSON 端点没有体积上限；**v2 变更** 默认 1 MiB、ops 批量 8 MiB，超限 413。

### 1.5 限流（图片上传）
- **MUST** 每个设备每分钟最多 **30** 次 `POST /api/v1/images`（滑动窗口 60000ms，按已认证设备分别计数）。
- **MUST** 第 31 次起回 `429 rate_limited` + `retry_after_seconds`（整秒，向上取整 = 窗口内最早一次上传满 60 秒的剩余秒数）。
- **MUST** 被体积 / 格式拒绝的上传**同样计入**额度（限流检查在体积检查之前）。
- **MUST** 未认证的上传在限流之前就被 401 拒绝，**不消耗**额度。
- **SHOULD** 客户端收到 429 后按 `retry_after_seconds` 退避，**MUST NOT** 立即重试。
- **v2 变更** 该限流的数值与粒度不变。

### 1.6 压缩与分页
- **v1 现状** 无压缩（服务端从不设置 `Content-Encoding`），也没有流式响应：所有响应都是**整包 JSON**，大结果靠**参数分页** —— 操作日志用 `cursor` + `has_more`/`next_cursor`，全量快照用 `limit`（默认 200，上限 1000）+ `offset` + `has_more`/`next_offset`。
- **MUST NOT** 在 v1 上假设任何响应被压缩、或可以被增量解析。
- **v2 变更** 大 JSON（ops 批量、快照）支持 `Content-Encoding: gzip`，并改为 **NDJSON 流式分页**；v1 的整包 JSON + `limit/offset` 语义在兼容层保持不变。

### 1.7 重试与幂等（传输层约束）
- **v1 现状** HTTP 层**不做**自动重试，失败直接报给上层；不使用 `Retry-After` 响应头，重试节奏只由 body 里的 `retry_after_seconds` 表达。
- **MUST** 幂等键固定为：图片 = `image_hash`、任务 = `task_id`、操作日志 = `op_id`；所有 GET 天然幂等。
- **MUST** 客户端在幂等请求上重试时必须复用同一个键（否则会重复计费/重复分析）。
- **v2 变更** 只对 GET 与上述幂等 POST 重试，退避 **1s / 3s / 10s**；4xx（除 408 / 429）不重试；429 用 `retry_after_seconds`。

### 1.8 WS 失联与重连
- **MUST** 客户端退避重连：**1s / 2s / 5s / 10s / 30s**（此后保持 30s 上限）。
- **MUST** 握手被拒 401 / 403 时**停止**重连，并提示重新配对（现状：标记鉴权失败、转轮询）。
- **MUST** 收到 `device_revoked` 且 `device_id` 是自己时立即断开并清除本地配对信息。
- **MAY** 各端自行使用 WS 控制帧 ping/pong（传输层细节，不进契约）；现状客户端每 20s 发一次，服务端不感知。

## 3. 一致性向量覆盖

| 规则 | 覆盖它的向量 |
|---|---|
| 单图 ≤ 2 MiB、边收边判、不等整包 | `images.ndjson` 10（2097153 字节 → 413 `payload_too_large`） |
| 空文件 → 400 | `images.ndjson` 9 |
| 上传限流 30/分钟/设备，且被拒请求计入 | `images.ndjson` 11（补齐额度，其中含 1 次超限 + 1 次空文件）、12（第 31 次 429 + `retry_after_seconds`） |
| 上传 / 下载都要求鉴权（401 早于限流） | `images.ndjson` 13、14（401） |
| 明文 + 实际端口 | 间接：全部向量以 `http://127.0.0.1:$port` 发起 |
| 操作日志分页（`cursor` / `has_more` / `next_cursor`） | `sync.ndjson` 18、19（游标推进到空页时 `next_cursor` = null） |
| 快照分页（`limit` / `offset` / `has_more` / `next_offset`） | `sync.ndjson` 28、29 |
| WS 同端口 `/ws`、心跳、重连退避 | **缺口**（`ws` 操作待实现） |
| 建连 / 读超时、发送超时 | **缺口**（回放器不断言超时） |
| 路由静态段优先（`/tasks/active` 不被参数路径抢走） | **缺口**：四组向量都没打 `/api/v1/tasks/active` |

## 4. 文档-实现分叉

| 现有文档怎么写 | 实现是什么 | 处置 |
|---|---|---|
| 「客户端在每个请求带上 `X-QS-Client-Version`；服务端响应带 `X-QS-Server-Version`」 | `/ws` 完全绕过中间件：WS 握手**既不检查版本、也没有** `X-QS-Server-Version` 响应头 | 规范按实现写：版本头只覆盖 `/api/*`（详见 `10-versioning.md`） |
| 「客户端 10s 内未回 `pong` 则断开重连」 | 服务端**不**校验 `pong`、**不**主动断开；客户端判据是「>40s 未收到服务端 `ping`」 | 规范写明现状判据是 40s 静默；v2 目标才是服务端校验 pong + 90s 断开 |
| WS 事件表列了服务端 → 客户端的 `ops` 事件 | 实现里没有这个广播（实际只有 `hello`、`ping`、`task_update`、`task_result`、`task_failed`、`collection_changed`、`device_revoked`）；客户端 → 服务端的 `push_ops` + `ack` 才是实现的路径 | 规范把服务端 → 客户端的 `ops` 标为**未实现**，不得依赖 |
| 「端口默认 8765，被占用依次尝试 8766–8770」（未说全占满怎么办） | 6 个都占用 → 启动失败并报错 | 规范补写「全部占用 = 启动失败」，禁止静默换端口 |
| 「实际端口写入配对二维码与 `/api/v1/info`」 | `/api/v1/info` 的响应体里**没有**端口字段（向量 1 的期望键里也没有） | 规范改写为「端口只从配对二维码 / 用户手输获得」；若要在 `/info` 暴露端口，须作为 v2 的加法字段另立 |
| 「客户端限流：每分钟 30 次」（未说计数口径） | 按**已认证设备**分别计数，且 413/400 被拒的上传也占额度 | 规范写明口径 |
| 明文 HTTP 只写了「局域网明文」 | 客户端另有 20s 间隔的 WS 控制帧 ping，服务端不感知 | 标为传输层细节，不写进契约 |
